## What this task actually is
User asked to implement all 8 GiftQuest screens (Home in 3 states, Add/Edit Wish,
Pairing tab in 2 states, Guess chat, Win/Lose reveal in 2 states, Login/Signup,
Settings) per docs/giftquest_ui_spec.md ("giftquest_ui_spec (1).md" on disk) and
docs/"# GiftQuest UI Mockups.pdf", using the existing Sunset Pop theme tokens.

IMPORTANT CONTEXT: there was already a *previous* implementation of Home/Pairing/
GuessChat/AddEditGift/Login/Signup from an earlier session (see DEV_LOG.md,
"Sunset Pop redesign" entry) — but it used a different, looser design (grids
instead of lists, 8-guess cap instead of 5, no visibility/locked-wish concept,
no wrapped/gifted status, no Settings screen, no real QR code, no Reveal screen).
This task is a redesign pass that supersedes that work, rebuilding the UI layer
to match the new spec/mockups exactly while keeping the working Firestore/Groq
plumbing (repositories, GroqApiClient, GiftContextFetcher) intact underneath.

## The two open items — RESOLVED, do not re-ask
1. "Wrapped" status → renamed to **"gifted"**. Trigger: the GUESSER marks it
   gifted (not the wisher) — single-step tap, no confirmation dialog, updates
   immediately. Rationale from user: "the guesser is the one who received the
   physical gift, so they're the one confirming it happened." Implemented as
   GameResult.gifted (bool) + giftedAt, guesser-driven via markGifted().
2. "Brag to partner" / "share the fail" buttons → DROPPED ENTIRELY. User: "we
   try to guess the gift without the wisher really knowing we did or not
   otherwise it beats the element of surprise." Do NOT add any share/notify
   button on the reveal screen. On WIN, that button slot is repurposed for a
   "mark as gifted" action instead (see below). On LOSE, there's no primary
   action at all — just "back to home".

- pubspec.yaml: added qr_flutter ^4.1.0 (real QR rendering, pure Dart) and
  mobile_scanner ^7.1.2 (real camera QR scanning, per spec's "scan QR code
  (opens camera)"). `flutter pub get` already run successfully.

  camera uses-feature, for mobile_scanner.
- ios/Runner/Info.plist: added NSCameraUsageDescription AND

  for image_picker's existing gallery usage — latent bug, fixed while here).
- lib/config/game_config.dart: added `maxGuesses = 5` (spec: "capped, 5 by
  default... tweakable value, not hardcoded").
- lib/models/gift.dart: renamed `note` → `hint` (Firestore field renamed too;
  fromFirestore falls back to reading old `note` key for back-compat, doesn't
  matter much since no real users yet). Added `GiftVisibility` enum
  (onPairing/onDate/manual), `visibility`, `unlockAt` (DateTime?),
  `revealedManually` (bool). Added `Gift.isLocked({required bool isPaired})`
  computing lock state from visibility.
- lib/models/game_result.dart: added `gifted` (bool) + `giftedAt` (DateTime?).
- lib/models/user_profile.dart: added `pendingPairRequestTo` /
  `pendingPairRequestFrom` (uid strings) for the new pairing-request flow
  (see below — pairing is no longer instant/symmetric).
- lib/models/chat_message.dart: GameState enum `givenUp` renamed to `lost`
  (there's no more manual "give up" — every message is a guess, loss is
  auto-triggered when guesses run out). Updated doc comment.
- lib/repositories/gifts_repository.dart: addGift/updateGift take `hint`
  (renamed from note), `visibility`, `unlockAt`. Added `revealNow()` for the
  owner to manually unlock a `manual`-visibility wish early.
- lib/repositories/game_results_repository.dart: `saveGameResult` now RETURNS
  the new doc's id (needed by the reveal screen to call markGifted later).
  Added `markGifted({itemOwnerId, resultId})` and
  `streamAllResultsForOwner(ownerUid)` (all results against MY OWN gifts,
  any guesser — needed for Home's own-wish-list status badges: "hidden" /
  "guessed by [partner]" / "gifted").
- lib/repositories/pairing_repository.dart: REWORKED. Old behavior linked both
  users instantly/symmetrically in one batch. New behavior implements a real
  request/accept flow because the spec explicitly requires a "waiting for
  partner to confirm" state, which is impossible with instant linking:
    - `sendPairRequest({myUid, partnerCode})` — sets myUid.pendingPairRequestTo
      = partnerUid, partnerUid.pendingPairRequestFrom = myUid. Does NOT link.
    - `acceptPairRequest({myUid, requesterUid})` — sets linkedWith both ways,
      clears both pending fields. This is what actually links two accounts now.
    - `declinePairRequest({myUid, requesterUid})` — clears pending fields, no
      link.
    - `cancelMyPendingRequest({myUid, partnerUid})` — lets me cancel a request
      I sent while still waiting.
    - `unlinkMe` / `ensureMyShareCode` unchanged.
- lib/providers/pairing_providers.dart: REWROTE PairingController to match the
  new repo methods (sendPairRequest/acceptPairRequest/declinePairRequest/
  cancelMyPendingRequest/unlink). Added `myOwnGameResultsProvider` (streams
  streamAllResultsForOwner for the signed-in user — for Home's own-list
  status). Old `linkWithPartnerCode` method/provider is GONE, replaced.
- lib/providers/guess_chat_providers.dart: REWROTE.
    - GuessChatState gained `item` (Gift?, loaded up front now even on the
      already-played path — previously `_item` was a private field only set
      on the fresh-game path, which would have left the reveal screen with
      nothing to show for a replay). Also gained `resultId` (String?) and
      `gifted` (bool).
    - `_load()` now ALWAYS fetches the Gift first (title/hint/category/price/
      photo needed by the reveal screen regardless of path), THEN checks for
      an existing GameResult. If one exists, state is set directly to
      GameState.won/lost (not a separate "alreadyPlayed" branch minus data)
      with guessCount/resultId/gifted all populated from the saved result —
      so re-opening an already-finished wish can go straight to the Reveal
      screen with full data, no special-casing needed downstream.
    - `sendGuess()`: on a correct guess, saves result, captures resultId. On
      an incorrect guess where guessCount has now hit GameConfig.maxGuesses,
      AUTO-finalizes as a loss (saves result, captures resultId) — no manual
      give-up button/flow anymore, matches the mockup (input row is just a
      text field + send button, no separate "give up" affordance).
    - `_gamePrompt()`: updated to reference `item.hint` instead of `item.note`,
      reworded the prompt so hint is explicitly "the only extra evidence you
      may draw on" (spec: "hint = the only evidence the AI is allowed to draw
      on").
    - Added `markGifted()` — calls the repo, updates local state.gifted.
- lib/theme.dart: added `AppColors.success` (mint green, `#A8E6C1`) and
  `AppColors.onSuccess` for the win-state reveal screen icon — this isn't a
  ColorScheme slot (Material's scheme has no "success" concept), so it's a
  plain static like the other AppColors tokens, used directly rather than via
  Theme.of(context).colorScheme.
